# Hyprland: hyprlang (.conf) → Lua migration

Hyprland deprecated the hyprlang `.conf` format in 0.55 and removes it in
**0.57**. This config was migrated on **2026-08-21**, while running 0.56.2.

## How Hyprland picks a config

At startup Hyprland looks for `~/.config/hypr/hyprland.lua` first, and only
falls back to `hyprland.conf` if it is absent:

```
[cfg] Lua config not found, using legacy config at ~/.config/hypr/hyprland.conf
```

**The entire `.conf` tree is still present and unmodified.** Nothing was
deleted. Switching between the two is a rename.

## Rollback (instant, no data loss)

```sh
mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.disabled
```

Then log out and back in. Hyprland finds no `hyprland.lua` and loads
`hyprland.conf` exactly as before. To re-enable, rename it back.

The scripts under `scripts/` detect which parser is live at runtime (see
`scripts/hypr-compat.sh`), so they keep working either way.

If you are ever locked out with a broken config, from a TTY (Ctrl+Alt+F2):

```sh
mv ~/.config/hypr/hyprland.lua ~/.config/hypr/hyprland.lua.disabled
```

## Layout

```
hyprland.lua          entry point; requires the modules below in the same
                      order the old hyprland.conf sourced its .conf files
lua/defaults.lua      apps + paths (was 01-UserDefaults.conf and the repeated
                      $variable blocks)
lua/colors.lua        wallust output (generated; see below)
lua/env.lua           environment variables
lua/settings.lua      input, misc, cursor, gestures, layouts
lua/decorations.lua   borders, blur, shadow
lua/animations.lua    curves + animation leaves
lua/windowrules.lua   vendor window/layer rules
lua/userwindowrules.lua   your window/layer rules
lua/keybinds.lua      default keybinds
lua/userkeybinds.lua  your keybinds
lua/laptops.lua       laptop keys + touchpad device
lua/startup.lua       exec-once equivalents
monitors.lua          generated by nwg-displays
workspaces.lua        generated by nwg-displays
```

Validate any change before logging out:

```sh
Hyprland --verify-config -c ~/.config/hypr/hyprland.lua
```

Or test it fully in a nested window without touching your session:

```sh
Hyprland -c ~/.config/hypr/hyprland.lua
```

## Runtime API changed too

Under a Lua config, `hyprctl keyword` is refused and `hyprctl dispatch` takes a
Lua expression rather than a legacy dispatcher name:

```sh
hyprctl keyword decoration:blur:size 5      # legacy only
hyprctl eval 'hl.config({ decoration = { blur = { size = 5 } } })'   # lua

hyprctl dispatch exit 0                     # legacy only
hyprctl dispatch 'hl.dsp.exit()'            # lua
```

`getoption`, `clients`, `activewindow`, `monitors` and `binds` are unchanged.

Six scripts used the legacy calls and now go through `scripts/hypr-compat.sh`,
which picks the right form at runtime:
ChangeBlur.sh, ChangeLayout.sh, KeybindsLayoutInit.sh, TouchPad.sh,
GameMode.sh, Dropterminal.sh.

## Deliberate differences from the old config

1. `Super+1..0` are bound to plain digits instead of `code:10..code:19`.
   `code:NN` is currently **broken** in 0.56.2's Lua parser - it silently
   produces a bind with neither key nor keycode. Equivalent on a `us` layout.
   **Re-test `code:` after upgrading to 0.57.**
2. `XF86AudioPlayPause` bind dropped - not a real xkb keysym, so it never
   fired under hyprlang either. `XF86AudioPlay` covers the same key.
3. `borderangle` animation speed clamped 180 → 100 (Lua schema maximum).
   Not visible: borderangle only animates gradient borders.
4. Three `idle_inhibit` rules matching `^(*)$` (an invalid regex) and a
   duplicate `match:fullscreen 1` rule were dropped as no-ops.
5. `Alt+Tab` was two binds in hyprlang; now one Lua function doing both.
6. `workspaceopt allfloat` (Super+Alt+Space) no longer exists as a
   dispatcher; reimplemented in Lua over the active workspace's windows.

## Known pre-existing issues (not caused by the migration)

- `scripts/Tak0-Autodispatch.sh` uses `windowrulev2`, removed back in 0.53.
  It is already broken and was left alone.
- Four keys are bound twice, and the first bind wins:
  `Super+M` (split ratio vs Spotify), `Super+Shift+E` (quick settings vs file
  manager), `Super+Shift+F` (fullscreen vs browser), `Super+Ctrl+Shift+Print`
  (screenshot in 10s vs screenshot to clipboard). The Lua config preserves the
  existing order, so behaviour is unchanged - but the second bind in each pair
  has never worked.
